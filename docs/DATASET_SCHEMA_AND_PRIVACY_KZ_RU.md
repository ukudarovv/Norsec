# Схема данных и приватность (KZ/RU)

Документ сопоставляет записи Hugging Face Dataset с вашей операционной политикой и законами о персональных данных Казахстана и (при применимости) РФ. Юридическую финализацию выполняет локальный комплаенс; здесь — инженерный минимум для публикации и gated-доступа.

## Слои на Hub

| Слой | Видимость | Содержимое | Типичные ПДн |
|------|-----------|------------|--------------|
| **Public proxy** | Публичный или лицензированный community | Нормализованные тексты из открытых корпусов (Jigsaw, OLID, TRAC, Ru-* и т.д.) | Обычно мало/нет прямых идентификаторов; проверяйте лицензию источника |
| **Gated domain** | Private / gated request | Транскрипты/метаданные с площадок заказчика | Речь, поведенческие метки, место/время — высокий риск |
| **Synthetic / demo** | Публичный | Ручной `fixtures/*.jsonl` для тестов пайплайна | Нет реальных субъектов |

## Каноническая схема (уровень `utterance`)

Поля реализованы в [`hf_ml_verbal/schemas.py`](../hf_ml_verbal/schemas.py).

- `example_id`: стабильный UUID/хеш содержания (не ФИО/ID камеры в публичных сплитах).
- `text`: нормализованный текст (после детокс-санитизации при необходимости).
- `lang_primary`, `lang_tags`: например `ru`, `kz`, `mixed`.
- `source_id`, `license_spdx`: откуда строка и под какой лицензией она переиспользуется на Hub.
- `split`: train/val/test или domain-specific folds.
- `scene_coarse`: грубый контекст (`corridor`, `classroom`) **без** точного геокода.
- Для мультильмабелей: см. ниже классы вербальной угрозы.

Эпизодный уровень (`episode_*` в коде опционально) хранится только в gated-слое и не должен включать биометрические вторичные данные лица как целевую метку для школьного/workplace кейса.

## Классы вербального риска (рекомендация из ТЗ)

Маппится в столбцы датасета `labels_*` или multihot-схемой — см. `config/verbal_labels.yaml`.

1. **neutral_conflict** — разовый конфликт без доминирования/угрозы.
2. **insult_humiliation** — унижение/оскорбление.
3. **explicit_threat** — явная угроза насилием или вредом.
4. **coercion_harassment** — принуждение, преследование, давление во времени.

Эти признаки в продукте сводятся с **видеопрокси драки/насилия** (`violence_probability` по кадрам без bounding box — см. код `inference/incident_signals.py`): это не детектор инцидента в юридическом смысле и допускает ложные срабатывания (спорт, бег).

## Матрица ПДн (шаблон для README на Hub)

Заполните перед публикацией gated/public репозитория:

| Вопрос | Ответ (заполняет владелец данных) |
|--------|-----------------------------------|
| Цель обработки | Раннее выявление кандидат-событий для human-in-the-loop |
| Правовое основание | (заполнить по KZ закону о персональных данных и внутренним актам) |
| Категории субъектов | учащиеся / сотрудники / посетители |
| Перечень ПДн | голос / транскрипт / временные метки / площадка |
| Срок хранения | например X дней после разрешения инцидента |
| Третьи лица | HF только как технический хостинг при gated режиме (уточнить DPA) |
| Трансграничность | нужен ли transfer assessment |
| Права субъекта | доступ/исправление/удаление — контакт |

## Сплиты

- Группировка по **площадке/источнику** (`source_id`), чтобы исключить утечку одного канала между train/test.
- Для смеси языков держите стратифицированные срезы `ru_only`, `kz_only`, `mixed` для отчётности в карточке модели.

## Минимизация

Для открытых выгрузок: без ФИО, без точных временных меток камеры в одной строке с голосом, без URL с идентификаторами. Для текстовых прокси — только то, что разрешено лицензией источника.
